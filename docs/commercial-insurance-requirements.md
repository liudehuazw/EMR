# 商保报销功能需求说明

**创建日期**：2026-07-18  
**状态**：已确认，进入开发  
**最后更新**：2026-10-22（商保报销基数修订：改为 个人账户支付 + 个人现金支付，并取消硬性上限拦截）

## 1. 背景

在发票统计模块中，用户需要记录「商业保险已报销」的金额，并在汇总区实时看到：

- **商保报销**：当前患者、当前日期筛选范围内，已勾选并保存的商保金额合计  
- **实际自付**：自付金额 − 商保报销  

**说明**：系统原有「医保金额」来自 OCR，与「商保报销」相互独立，不得复用。

**关联**：其中「自付金额」的口径在 2026-10-21 明确为「**个人现金支付**」（详见第 3 节修订说明）—— 医保统筹、其他支付、个人账户支付均**不属于**自付。

## 2. 界面

### 2.1 汇总栏

在「自付金额」与「异常提醒」之间增加两个展示块：

1. 商保报销  
2. 实际自付  

统计范围与现有汇总一致：当前选中患者 + 日期筛选。

### 2.2 单张发票

在「关联病历」右侧依次为：

1. 非点击标签：`已由商保报销`  
2. 复选框（勾选 / 取消）  
3. 数字输入框（未勾选时禁用）  
4. `保存` 按钮  

## 3. 业务规则（已确认）

| 规则 | 约定 |
|------|------|
| 取消勾选 | 方案 A：取消勾选后点「保存」→ 该票商保金额清零，不再计入汇总 |
| 未勾选时输入框 | 禁用 |
| 商保金额上限 | **无硬性上限**：仅校验「有效数字且 ≥ 0」，不再阻断保存 |
| 参考基数 | 该票「**个人账户支付 + 个人现金支付**」（`account_payment + self_pay_amount`），超出仅记日志 |
| 统计范围 | 与当前患者 + 日期筛选一致 |
| 演示账户 | 不落库（与现有演示逻辑一致，仅前端临时生效） |

> **2026-10-22 修订：商保报销基数（重要）**
>
> 原规则把上限钉在「个人现金支付」上，但**个人账户支付**使用的是医保个人账户余额，同属患者自有费用，实际也会经过商业保险报销。故调整为：
>
> 1. 「已全部由商保报销」按钮填充值 = **个人账户支付 + 个人现金支付**
> 2. 保存时**不再按上限硬性拦截**，只校验「有效数字且 ≥ 0」
> 3. 超出参考基数时仅 `console.warn` 记录，不阻断用户保存
> 4. 缺支付构成的老数据，按 `总额 − 医保统筹 − 其他支付` 反推（等价于 账户 + 现金）
>
> 典型案例（上海门诊票据）：总额 913.13 = 统筹 174.66 + 个人账户 52.84 + 个人现金 685.63，
> 实际商保报销 **738.47** = 52.84 + 685.63。旧逻辑上限取 685.63，导致 738.47 被误拦。

> **2026-10-21 历史修订：商保上限口径**（已被 10-22 修订取代）
>
> 原规则为「不得超过自付金额；**无自付时不得超过发票总金额**」。发票解析器重构后，自付金额已能被正确识别（此前 6 张医保票自付恒为空），且旧兜底会把**医保已支付部分**也算进商保报销，故收紧为：
>
> 1. 优先取 `self_pay_amount`（**个人现金支付**）
> 2. 缺该值但存在支付构成时，按 `总额 − 医保统筹 − 其他支付 − 个人账户` **反推现金**
> 3. 仅当毫无支付构成（全自费票）才退回发票总额
> 4. 全额医保票（现金为 0）上限为 `0`，不可报销
>
> 详见 `DEVELOPMENT_LOG.md`「2026-10-21 — 发票解析器重构」。

## 4. 计算公式

```
商保报销 = Σ(已勾选且已保存的 commercial_amount)
实际自付 = max(0, 自付金额合计 − 商保报销)
```

## 5. 数据字段

表 `emr_invoice` 新增：

| 字段 | 类型 | 说明 |
|------|------|------|
| commercial_reimbursed | TINYINT | 是否已由商保报销（0/1） |
| commercial_amount | DECIMAL(12,2) | 商保报销金额 |
